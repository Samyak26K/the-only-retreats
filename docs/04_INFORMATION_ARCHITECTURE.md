Version: 1.0

# Purpose

This document defines the complete information architecture of The Only Retreats.

It explains:

• Website hierarchy

• Navigation

• User journeys

• Relationships between pages

• Content flow

• Future scalability

This document is the structural blueprint of the website.

It does NOT define UI design.

It defines where information belongs.

---

# Core Principle

Visitors should discover products naturally through stories.

The architecture follows:

Land

↓

People

↓

Tradition

↓

Product

↓

# Content Ownership

Every page should receive content from the typed content layer where applicable.

Avoid hardcoded UI copy.

Business logic should remain independent of content.

---

# Navigation Principles

Navigation should guide visitors.

Never overwhelm them.

Every click should reveal deeper understanding.

The website should feel like exploring the Himalayas—not browsing a marketplace.

---

# Scalability Principles

The architecture should support:

100+ products

50+ journal articles

25+ valleys

Multiple languages

CMS-driven content

International expansion

Without requiring major structural changes.

---

# Final Principle

The information architecture exists to tell one connected story.

Every page should answer one question:

"What should the visitor discover next?"

If a page cannot answer that question, it should be redesigned.
